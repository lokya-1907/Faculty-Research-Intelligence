# Architecture

React/Vite frontend -> FastAPI backend -> SQLite persistence -> Scopus Search publication adapter / official VFSTR CSE directory provider / Google Scholar provider adapter.

The frontend never stores API keys. Source calls happen only on the backend. Current Scopus Search responses are exposed as publication records and do not establish an author identity. Assigning publications to a faculty profile requires a verified Scopus Author ID; official author resolution is a separate, entitlement-gated adapter path. The VFSTR directory is stored separately from legacy faculty rows and returns only verified records from the official VFSTR CSE faculty directory, with its source URL and institution association. April 2026 Scholar/Scopus metrics are imported from the supplied spreadsheet only for unique normalized-name or exact token-set matches to official identities; fuzzy candidates are report-only, and the importer never calls Scopus Author Search. The current sheet has 94 rows: 39 safe matches, 7 ambiguous matches, and 48 unmatched rows (42 with fuzzy suggestions, 6 without candidates). The combined source-specific snapshot is dated `2026-04`, preserves source status, and keeps blank metrics null. Metric snapshots are upserted per faculty/source/date and distinguish dataset snapshots from actual sync runs. Search history stores faculty ID and timestamp, not API credentials.
